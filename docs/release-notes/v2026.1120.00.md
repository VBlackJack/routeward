# RouteWard v2026.1120.00

Hardening and reliability release: a hardened Windows named pipe and privilege checks, Linux fail-closed after a crash with the kill switch, your previous system proxy restored when RouteWard turns it off, a clean uninstall for every logged-on user, real DNS answers for DNS servers running on the host, and blocked TCP connections refused at once on Windows.

## Security

- **Named pipe (Windows)**: standard users allowed on the pipe can no longer create their own pipe instance, the daemon's pipe is owned by `BUILTIN\Administrators`, and clients refuse a pipe owned by anyone else before sending anything. A squatted pipe name is reported as such instead of "already running".
- **Privilege checks (Windows)**: `routeward daemon`, `run`, `cleanup --all-users` and `purge-data` require an enabled Administrators membership or the SYSTEM account; a restricted administrator token or `LOCAL SERVICE` is refused at the start.
- **Fail closed after a crash (Linux)**: when the daemon crashes or is killed while interception runs with the kill switch on, outgoing traffic stays blocked (loopback, established connections, DHCP and IPv6 neighbour discovery excepted) until `routeward cleanup --force`, `routeward ctl start` or a clean `systemctl restart routeward`. A clean stop never leaves the network blocked.
- **UDP fragments (Windows)**: later fragments of a UDP datagram follow the first fragment's verdict; an orphan fragment is dropped when the kill switch is on.
- **Desktop**: the WebView stays on the local UI origin and cannot open new windows, the local UI server bounds unauthenticated connections so another process cannot starve it, and developer tools exist in debug builds only.
- **systemd unit (Linux)**: hardened with a system call filter, kernel and control group protection, and restricted address families and namespaces.

## Fixed

- **System proxy and PAC (Windows)**: turning them on saves your previous settings and turning them off restores them, as long as the values are still RouteWard's, so a corporate proxy is no longer lost. The desktop also restores them when it exits and at logoff.
- **Uninstall**: `%ProgramData%\RouteWard` is removed unless `KEEPDATA=1` is passed (never on upgrade), and RouteWard's proxy, PAC and autostart values are removed or restored for every logged-on user. The cleanup output reaches the MSI log (`msiexec /x ... /l*v`). On Linux, `purge` removes `/etc/routeward` and `/var/log/routeward`.
- **DNS servers on the host**: Windows `dns.exe` and, on Linux, `named`, `unbound`, `dnsmasq`, `pihole-FTL`, `pdns_recursor`, `kresd`, `dnsdist` and `coredns` now get real DNS answers instead of Fake-IP ones, so a domain controller or LAN resolver no longer hands `198.18.x.x` addresses to other machines. `dnsConfig.dnsServerProcesses` adds processes or removes a default with `!name`; an explicit Block rule for the process still applies.
- **MSI upgrade**: the RouteWard service is no longer deleted; it is registered again with its `--allow-sid` arguments and restarted when it was set to start automatically. Uninstall no longer waits on the WinDivert driver.
- **Desktop**: the header follows engine changes made outside the UI (for example `routeward ctl start`), consecutive exports no longer trigger the "download multiple files" prompt, system errors are localized, dates, times, sizes and counts follow the UI language, and the process launcher takes one argument per line so arguments with spaces or quotes are passed unchanged.

## Changed

- **Blocked connections (Windows)**: a TCP connection blocked by a Block rule, the kill switch or the encrypted DNS block is refused at once with an injected TCP reset (a blocked `curl.exe` fails in about 4 s instead of waiting for its timeout). Blocked UDP (QUIC, DoQ and UDP Block rules) is answered with an injected ICMP Port Unreachable; on the Windows Server 2022 test machine that ICMP was not delivered, so those clients may still time out. Failed injections are logged.
- **Connections opened before start**: they keep their route until the application reconnects; on Windows the engine logs how many there are at start.
- **MSI**: bundles unmodified WinDivert 2.2.2 (LGPLv3) with its notices and removes its driver service on uninstall; each release attaches the WinDivert source archive. The portable ZIP still uses `tools/fetch-windivert.ps1`.
- **Requirements**: Rust 1.89 or later to build, Node.js 22.12 or later for the UI.

## Upgrade Notes

- **Update the desktop and the daemon together**: clients older than this release cannot connect to a daemon from this release (stricter pipe checks).
- **Profiles**: a profile that sets `dnsConfig.dnsServerProcesses` is refused by older daemons; an empty list is not written, so other profiles stay compatible.
- **Hosts that are DNS servers**: local applications on that host resolve through the local server and no longer get Fake-IP answers; domain rules then rely on TLS SNI and HTTP Host only. On a NetworkManager desktop that uses dnsmasq as its local resolver, add `!dnsmasq` to keep Fake-IP.
- **Uninstall keeps nothing by default**: pass `KEEPDATA=1` to keep the profile and logs.

## Windows Upgrade and Verification

- Download `routeward-2026.1120.0-windows-x64.msi` (upgrades earlier builds via `MSI ProductVersion 26.11.2000`) or `routeward-2026.1120.0-windows-x64.zip`.
- Verify checksums against `SHA256SUMS.txt` or the individual `.sha256` files.
