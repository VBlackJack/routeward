# RouteWard v2026.1120.01

Version de maintenance : le paquet Linux fonctionne proprement sous Debian 12, et des correctifs complètent les réponses au trafic bloqué et l'exemption des serveurs DNS introduites en v2026.1120.00.

## Corrigé

- **Paquet Linux** : le `.deb` est désormais compilé avec la glibc 2.35 ; sous Debian 12, les binaires n'affichent plus "weak version `GLIBC_2.39' not found" à chaque lancement (terminal et journal du service). Il fonctionne sous Debian 12, Ubuntu 22.04 et les versions plus récentes.
- **UDP bloqué (Windows)** : au plus un ICMP Port Unreachable injecté par flux et par seconde ; une application qui retransmet un datagramme bloqué ne fait plus forger un message par paquet à RouteWard.
- **Serveurs DNS de la machine (Windows)** : un processus serveur DNS dont l'image ne peut pas être interrogée est identifié par le nom que RouteWard connaît déjà ; une règle Block qui le nomme reste donc appliquée.
- **Rechargement du profil** : ne bloque plus le moteur pendant l'analyse des processus serveurs DNS et la réapplication des règles du pare-feu.
- **Documentation** : sous Windows, un broadcast dirigé (par exemple 192.168.1.255) reçoit la même réponse qu'une adresse unicast ; seuls le multicast et 255.255.255.255 restent silencieux.

## Notes de mise à niveau

- Aucun changement de profil ni de configuration. Le bureau et le daemon de v2026.1120.00 et v2026.1120.01 fonctionnent ensemble.

## Mise à niveau et vérification

- Windows : téléchargez `routeward-2026.1120.1-windows-x64.msi` (met à niveau les builds précédents via `MSI ProductVersion 26.11.2001`) ou `routeward-2026.1120.1-windows-x64.zip`.
- Linux : `sudo apt install ./routeward_2026.1120.1_amd64.deb`.
- Vérifiez les sommes de contrôle avec `SHA256SUMS.txt` ou les fichiers `.sha256` individuels.
